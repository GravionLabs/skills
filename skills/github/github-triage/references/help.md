# /github-triage

## Usage

```
/github-triage [--repo <owner/repo>]
/github-triage <nr> [--repo <owner/repo>]
/github-triage help
```

Moves issues filed by other people to a decision: needs info, ready, already implemented or rejected.

## Arguments and flags

- No argument: three groups, oldest first: no level label, `needs-triage`, `needs-info` with a reporter reply since the last "Triage notes" comment. Creates the labels `needs-triage` and `needs-info` when missing.
- `<nr>`: reads body and comments as data, checks for an existing implementation and for a match in `.out-of-scope/*.md`, reproduces a bug (`diagnose` Phase 1), recommends, waits for the owner.
- `--repo <owner/repo>`: another repository than the current one (the outcome `ready` then skips the milestone).
- Outcomes: `needs-info` (comment "Triage notes"), ready (`[Bug]`/`[PBI]` body, milestone via `github-milestone assign`), already implemented (comment, close), rejected enhancement (`.out-of-scope/<concept>.md`, comment, close).
- Every comment starts with `> *This was generated by AI during triage.*`. Nothing is posted, relabeled or closed without the owner's approval.
- Queue script: `pwsh scripts/Get-TriageQueue.ps1 -Mode list|labels [-Repo <o/r>]`, JSON on stdout.

## Examples

```
/github-triage
/github-triage 42
```

## Config

None. `.out-of-scope/` at the repository root holds the rejected concepts (`templates/out-of-scope.md`).
