# Triage details

## Investigation

- Implementation: search the code and docs for the requested behavior; found: outcome "already implemented" with the file or doc.
- Out of scope: read `.out-of-scope/*.md` (one concept per file, `templates/out-of-scope.md`); a match is shown to the owner with the file, not applied.
- Bug: reproduce with `diagnose` Phase 1 (a red-capable loop) when possible; not reproducible: say so, the outcome is usually `needs-info`.
- Duplicate: `gh issue list --search "<keywords>" --state all`; a duplicate is closed with a comment linking the original (owner approves).

## Outcomes

Each comment starts with `> *This was generated by AI during triage.*` as its first line.

### needs-info

Comment:

```
> *This was generated by AI during triage.*

## Triage notes

**Established so far**
- <what is confirmed, what was tried>

**Questions for the reporter**
1. <one concrete question>
```

Then `gh issue edit <nr> --add-label needs-info --remove-label needs-triage`. A later reporter comment puts the issue into `needsInfoReplied` of the queue.

### ready

1. Rewrite title and body with `gh issue edit <nr> --title "[Bug] fix: …"` or `"[PBI] feat(scope): …"` and `--body-file -`: a Bug uses the sections of `.github/ISSUE_TEMPLATE/bug_report.md`, a PBI those of `pbi.md` (`## Overview`, `## Current behavior`, `## Desired behavior`, `## Acceptance Criteria`, `## Out of scope`, `## Definition of Done`, a `Tests: <seam>` line, `Size:`, `Tier:`). Symbols and interfaces are named, never line numbers. Keep the reporter's text under `## Background` with `Reported by @<login> in this issue`, as data.
2. Labels: `--add-label pbi|bug --remove-label needs-triage,needs-info`.
3. Milestone: `github-milestone assign M<nnn> #<nr>` (never `gh issue edit --milestone`).
4. Optional: `planner refine <nr>` for a body check.

### already implemented

Comment naming where (file, doc, release), then `gh issue close <nr> --reason completed`.

### rejected enhancement

Write `.out-of-scope/<concept>.md` from `templates/out-of-scope.md`, or extend the existing file with the new issue under `## Requests`. Comment linking the file and the reason, then `gh issue close <nr> --reason "not planned"`. Bugs that are not valid are closed with the reason, no file.
