# Group `delivery`

Skills of the `delivery` group and what each one does. Read before changing a skill of this group.

`poimen-lead` (a lead agent through the poimen MCP tools `start_agent`, `wait_agent`, `read_agent`, `prompt_agent`, `report_done`; no CLI; rules: when to split, one worktree per worker, never poll, blocked workers), `planner` (Epic → Features, Feature → PBIs, an L-sized PBI or Bug → sibling PBIs, no Task issues), `deliver` (Feature #686, formerly `deliver-min`: user-invoked `/deliver <nr> [--base <branch>] [--issue-file <path>] [--review-file <path>]` delivers one PBI or Bug as a pull request and never merges; `node scripts/deliver-loop.mts` with `--milestone <M>` or `--issues <nr,…>` (Node with type stripping, no build) starts one fresh session per ready issue in its own worktree, then a review session (`deliver-review`) in a fresh worktree at the pull request head, and merges the approved commit once every required check passed; `changes` starts the implementer again with `--review-file`, at most 2 fix rounds counted in the run; review settings `deliver.review.{model,harness,effort}`, `--review-model`, `--review-harness` in `scripts/review.mts`, which also validates the verdict; ADR 0009; `scripts/tracker.mts` is the tracker contract, `scripts/tracker/github.mts` the GitHub tracker, `scripts/harness.mts` the agent CLIs (`claude`, `copilot`), `scripts/events.mts` the agent-events writer; a fully delivered `--milestone` ends with the release pull request into the default branch (opened, never merged; an open `release-test` issue is reported as needs you and as an attention); a missing `release/next` is cut from the default branch; refuses a base without required checks, issues of authors without write access and pull requests that change protected paths; tests `test/skills/delivery/deliver.test.ts` with the fake tracker and harness in `test/skills/delivery/deliver/`, shared runner `deliver/run-loop.ts`, review cases `deliver-review.test.ts`), `deliver-review` (user-invoked `/deliver-review <nr> --base <base> --pr <url> [--issue-file <path>]`: reviews the pull request with the rules of `code-review`, writes `{ verdict: approve|changes, findings, unmet }` to `DELIVER_REVIEW_FILE`, posts one PR comment, never pushes), `grill-me`(interviews the user until no open decision is left; issue number, plan`questions[]`or free description; answers go under`## Decisions`), `retro`(user-invoked run retrospective; draft PBIs, and lesson drafts with`status: proposed`for repository-, language- or role-specific candidates,`references/lessons.md`), `handoff` (user-invoked `/handoff [focus] [--path <file-or-dir>]`, `/handoff help`: writes the session as `handoff-<yyyy-mm-dd>-<slug>.md` to the OS temp dir or the named path, sections Goal, State, Next steps, Open decisions, Suggested skills, Pointers, links instead of copies, secrets and personal data as `<REDACTED>`, never overwrites; no next session, no memory files; `references/template.md`, `redaction.md`), `roadmap` (user-invoked `/roadmap`, `/roadmap help`: assigns open Epics, Features, PBIs and Bugs to `M<nnn>` milestones after approval, `scripts/Get-RoadmapState.ps1`, `Set-IssueMilestones.ps1`, and writes `ROADMAP.md`, `New-Roadmap.ps1`, `references/proposal.md`, `references/roadmap-md.md`), `skills-manage`(user-invoked installer`scripts/Install-Skills.ps1`: detects the stack (a notes vault: `.nixe/` or `.obsidian/` without build file proposes `vault`, with `Profile.md` also `school`; both are outside the presets `core` and `all`), proposes groups, dry run first, then one `npx skills add GravionLabs/skills --skill …`call plus pinned external packs; slash usage`/skills-manage [dry-run] [group...] [-g]`, `/skills-manage update [dry-run] [-g]` (`-Update`: `npx skills check`, confirm, `npx skills update`, then new members of the installed groups from the refreshed `groups.json` are proposed); `scripts/groups.json`mirrors the marketplace groups;`references/groups.md`, `references/after-install.md`). After a project install (not `-g`) it offers `/project-setup`. Uses `github`and`shared`; stack groups are installed per project.
