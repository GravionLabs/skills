# Group `delivery`

Skills of the `delivery` group and what each one does. Read before changing a skill of this group.

`planner` (Epic → Features, Feature → PBIs, an L-sized PBI or Bug → sibling PBIs, no Task issues), `deliver` (Feature #686, formerly `deliver-min`: user-invoked `/deliver <nr> [--base <branch>] [--issue-file <path>]` delivers one PBI or Bug as a pull request and never merges; `node scripts/deliver-loop.mts` with `--milestone <M>` or `--issues <nr,…>` (Node with type stripping, no build) starts one fresh session per ready issue in its own worktree and merges its pull request once every required check passed; `scripts/tracker.mts` is the tracker contract, `scripts/tracker/github.mts` the GitHub tracker, `scripts/harness.mts` the agent CLIs (`claude`, `copilot`), `scripts/events.mts` the agent-events writer; a fully delivered `--milestone` ends with the release pull request into the default branch (opened, never merged; an open `release-test` issue is reported as needs you and as an attention); a missing `release/next` is cut from the default branch; refuses a base without required checks, issues of authors without write access and pull requests that change protected paths; tests `test/skills/delivery/deliver.test.ts` with the fake tracker and harness in `test/skills/delivery/deliver/`), `grill-me`(interviews the user until no open decision is left; issue number, plan`questions[]`or free description; answers go under`## Decisions`), `retro`(user-invoked run retrospective; draft PBIs, and lesson drafts with`status: proposed`for repository-, language- or role-specific candidates,`references/lessons.md`), `roadmap` (user-invoked `/roadmap`, `/roadmap help`: assigns open Epics, Features, PBIs and Bugs to `M<nnn>` milestones after approval, `scripts/Get-RoadmapState.ps1`, `Set-IssueMilestones.ps1`, and writes `ROADMAP.md`, `New-Roadmap.ps1`, `references/proposal.md`, `references/roadmap-md.md`), `skills-manage`(user-invoked installer`scripts/Install-Skills.ps1`: detects the stack, proposes groups, dry run first, then one `npx skills add GravionLabs/skills --skill …`call plus pinned external packs; slash usage`/skills-manage [dry-run] [group...] [-g]`, `/skills-manage update [dry-run] [-g]` (`-Update`: `npx skills check`, confirm, `npx skills update`, then new members of the installed groups from the refreshed `groups.json` are proposed); `scripts/groups.json`mirrors the marketplace groups;`references/groups.md`, `references/after-install.md`). After a project install (not `-g`) it offers `/project-setup`. Uses `github`and`shared`; stack groups are installed per project.
