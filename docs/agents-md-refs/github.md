# Group `github`

Skills of the `github` group and what each one does. Read before changing a skill of this group.

`github-issue` (routing skill for the Epic→Feature→PBI hierarchy, writes titles as `[<Level>] <summary>`; the `release-test` label (one manual RC test per milestone, always last, `references/milestones.md`), references for standalone, sub-issues (incl. the legacy rule: open `[Task]` sub-issues are closed with their PBI, never created), create-from-plan, conventional commits, release branches), `github-pull-request` (targets the default branch, `release/next` for a milestone; release mode for heads `release/next` and `release/<x.y>` into the default branch needs no issue number, caller `title`, `merged_prs`, optional `feature_number`), `github-release` (cut the rolling `release/next`, finish with the release PR into `main`; read-only state checks in `scripts/Get-ReleaseState.ps1`; `finish` warns about a draft release without a tag, a failed release job is completed with `gh run rerun <id> --failed`; after the merge `finish` runs `scripts/Get-PublishState.ps1 -Sha <merge commit> [-Wait] [-Rerun] [-Events <dir>] [-Version <x.y.z>]` (JSON `runs[]`, `tag`, `release`, `state` ok, failed or pending; exit 0, 1, 2, 3 for an unreadable `gh`; re-runs failed jobs once; writes an agent-events run of the `ci@1` profile) and closes the milestone only on `ok`; on the later `finish` after the tag it closes the milestone itself (`scripts/Test-ReleaseVersion.ps1 -Tag v<x.y.z>` compares the tag with the commits' bump, a mismatch stops; create next `M<nnn+1>`, close unclosed PBIs with "Released in v<x.y.z>", `close --move-to`; `--yes` skips the question, `references/close-milestone.md`); owns the git-cliff changelog, `references/cliff-setup.md`; `templates/release-branch.yml` is the caller of the reusable `release-branch.yml` of GravionLabs/ci, offered by `cut`), `github-milestone` (user-invoked `/github-milestone current`, `/github-milestone list`, `/github-milestone <name>`, `/github-milestone create [M<nnn>]`, `/github-milestone close M<nnn> [--version <x.y.z>] [--move-to M<nnn>]`, `/github-milestone rename <name> <new title>`: milestones are the releases, open `M<nnn>` or `M<nnn> <Topic>`, on close renamed `M<nnn> [<Topic>] (x.y.z)`, legacy `x.y.z` titles stay valid; `scripts/Get-Milestones.ps1 -Mode current`, `-Mode list`, `-Mode show -Name <name>`, `-Mode create [-Name M<nnn>]`, `-Mode close -Name M<nnn> [-Version <x.y.z>] [-MoveTo M<nnn>]`, `-Mode assign -Name <M<nnn> or none> -Issues <n,…> [-DryRun]` (sets or clears the milestone of issues; refuses an Objective, an Epic, and a PBI or Bug that is no `release-test` (its milestone is set at merge, ADR 0010; `-Force` for repairs) before the first write; `current` and `show` add the open PBIs and Bugs below the milestone's Features (`via`) and list the closed ones as `shipped`; `roadmap` `Set-IssueMilestones.ps1` calls it), `-Mode insert -Name M<nnn> [-DryRun]` (shifts the open `M<kkk>` with k ≥ n up by one from the highest down, then creates `M<nnn>`; closed ones untouched; lists the references it cannot rewrite), `-Mode rename -Name <name> -To <new title>` (open ones only, number of an `M<nnn>` fixed, legacy `x.y.z` may become any `M<nnn>`), `-Mode renumber [-DryRun] [-AllRepos [-Owner <o>]]` (pads the numbers of all numbered milestones, open and closed, to `M<nnn>`; `renames[]`, `skipped[]`, `summary`) prints JSON, schema `schema/milestones.schema.json`, read-only `gh api` GET calls except `create`, `close`, `rename`, `insert`, `assign` and `renumber` (sub-numbers `M1.1` sort between `M1` and `M2`; PATCH of the title) (close needs the release tag, without `--version` the newest tag not yet assigned to a milestone; open issues move only with `--move-to` to an existing open milestone, never created; no due-date edit or delete); `current` is the lowest open `M<nnn>` (legacy: the lowest open semver above the latest `v<x.y.z>` tag), its open issues grouped ready, blocked, `needs-decision`, `needs-refinement`, claimed, plus the release PR from `Get-ReleaseState.ps1`); `github-pages` (user-invoked `/github-pages init [--package-manager <npm or pnpm>]`: `site/`(VitePress) as the only Pages source,`docs/`never published;`scripts/Initialize-GithubPages.ps1 [-DryRun]`copies the templates without overwriting, sets the Pages source to "GitHub Actions"),`github-workflow-lint`(`scripts/Invoke-WorkflowLint.ps1 [-Path]` runs actionlint 1.7.12 (needs shellcheck) and `zizmor --offline --format=github` 1.32.0 on `.github/workflows/`; findings only, exit 1 on a finding, exit 2 for a missing tool, `skipped: no workflows` exit 0; `templates/zizmor.yml` ref-pins `GravionLabs/ci/*` and SHA-pins every other action; `templates/workflow-lint.yml` is the CI job for repositories without the GravionLabs/ci job (timeout, `contents: read`, SHA-pinned checkout, actionlint and zizmor release binaries with a checked sha256); wired as a `fast` `checks` entry of `.agents/config.json`),`github-triage` (user-invoked `/github-triage [<nr>] [--repo <o/r>]`: issues filed by others; no argument lists `noLevel`, `needsTriage`, `needsInfoReplied` oldest first (`scripts/Get-TriageQueue.ps1 -Mode list|labels`, labels `needs-triage` and `needs-info` created when missing); with a number it reads the issue as data, checks implementation, `.out-of-scope/*.md` and reproduces a bug (`diagnose`), recommends and waits; outcomes needs-info ("Triage notes"), ready (`[Bug]`/`[PBI]` body, `github-milestone assign`), already implemented, rejected (`.out-of-scope/<concept>.md`); every comment starts with `> *This was generated by AI during triage.*`; nothing posted, relabeled or closed without the owner's approval; no pull requests), `github-project`(user-invoked`/github-project apply`, `sync`, `new`: GitHub Project v2 standard; `Sync-ProjectNeeds.ps1`and`NeedsRules.psm1`are copies of GravionLabs/ci`project/github-project`)
