# Group `vault`

Skills of the `vault` group and what each one does. Read before changing a skill of this group.

All skills find folders only through the roles of `.nixe/config.json` of the vault (`folders`, default English names; `scripts/Get-VaultRoles.ps1` of `vault-inbox` prints roles, `language` and the template folder as JSON), write notes in the vault's `language` (a note's `lang` wins; frontmatter keys stay English) and name no Obsidian-only feature as required. Templates: `templates.folder`, then `.obsidian/templates.json`, then the role `templates`; a missing template falls back to the structure in the skill. Never delete or overwrite a note. The permissions the vault's `.claude/settings.json` needs are in `vault-inbox/references/vault-config.md`.

`vault-inbox` (merges the `inbox` skills of both vault templates; import in four phases: review, a proposal table, approval, import, nothing written before the approval; converts large photos, HEIC and scanned PDFs and moves the files out of the inbox, removing the unconverted original of a converted file; files into the standard roles and into own roles by their `description`; a note that fits no role stays in the inbox with a reason; never files into a folder without a role unless the user names it in a correction), `vault-clip` (verbatim clipping of a page into the `clippings` role), `vault-summarize` (structured summary note), `vault-meeting` (meeting note with action items), `vault-decision` (decision record), `vault-weekly-review` (review into the `journal` role), `vault-recipe` (recipe into the own role `recipes`; without the role it stops and points to `/vault-setup role recipes`).

`vault-setup` (`scripts/Invoke-VaultSetup.ps1`: `setup para|school [-Language en|de]` (the profiles combine in one vault: one language, another is refused; school on a vault with the role `areas` puts `subjects` below it; the school profile file is `files.school-profile`, `files.profile` is the fallback) creates folders, `.nixe/config.json` (existing entries kept), templates, the profile file and the profile section of `CLAUDE.md` and installs the profile's skills with `npx skills add` (`assets/profiles.json`; the school assets come from `school-summary`); `role <name> <path> [description]`, `role -List`, `role -Remove <name>` with the rules of Nixe; `attachments` and `inbox` never share a folder (`setup` and `role` refuse it, an existing vault gets a warning and the proposal `role attachments <Anhänge|Attachments>`); `update` runs `npx skills check` and `update` and replaces the core block of `CLAUDE.md` between `<!-- vault-core:start -->` and `<!-- vault-core:end -->` from `assets/core/CLAUDE-core.md`; text outside the markers is the vault's own; never overwrites a note, never commits; runs without a question when called with an argument).
